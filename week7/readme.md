# **포인터_증감연산_정리**

## **C 포인터 역참조·증감 연산 정리**

### **1. 기본 전제**

int num = 10;
int *pnum = &num;

이 상태를 기준으로 아래와 같은 표현식이 가능하다.

| **표현식** | **동작** |
| --- | --- |
| (*p)++ | 현재 값을 반환하고, 이후 값을 증가시킨다 |
| (*p)+1 | 값을 변경하지 않고 1만큼 더한 결과를 반환한다 |
| *p+=1 | 값을 1 증가시키고 결과를 다시 저장한다 |
| (*p)+=1 | *p+=1과 동일하다 |
| *p=*p+1 | 값을 1 더하고 결과를 저장한다 |
| ++*p | 값을 먼저 1 증가시키고, 증가된 값을 반환한다 |
| ++(*p) | ++*p와 동일하며, 연산 순서를 명확히 표현한 것 |

### **2. 핵심 원칙 ① — 우선순위는 "묶이는 순서"이지 "실행 순서/결과값"이 아니다**

- 단항 *는 +=, 전위 ++보다 우선순위가 **높다** → p+=1, ++*p는 괄호 없어도 자동으로 (*p)+=1, ++(*p)로 묶인다. **그래서 이 짝들은 결과가 완전히 동일하다.**

반면 **후위 ++/-*는 단항 보다 우선순위가 **더 높다.** 그래서:

p++ → (p++) 로 묶인다 (❌ (*p)++가 아님)

여기서 ++는 **포인터 p 자신**에 적용되는 것이지, 역참조된 값(p)에 적용되는 게 아니다.

> ⚠️ **흔한 오해**: "우선순위가 높다 → 먼저 실행된다 → 증가된 결과를 다음 연산이 쓴다"
이건 틀렸다. 우선순위는 **"누가 누구랑 묶이는가"**만 결정할 뿐, "부수효과가 끝난 새 값을 넘겨준다"는 뜻이 아니다.
> 

### **3. 핵심 원칙 ② — 후위 연산자는 "식의 결과값"과 "실행 후 상태"를 분리해서 봐야 한다**

| **구분** | **후위 ++ (a++)** | **전위 ++ (++a)** |
| --- | --- | --- |
| 식의 **결과값** | 증가하기 **전** 값 | 증가한 **후** 값 |
| 실행 후 **변수 상태** | 증가되어 있음 | 증가되어 있음 |

→ 둘 다 결국 변수는 증가하지만, **그 식 자체가 돌려주는 값이 다르다.** 이 두 가지(①식의 결과값, ②실행 후 변수 상태)를 분리해서 생각하면 헷갈리지 않는다.

#### **(*pnum)++ vs pnum++ 비교**

(*pnum)++   →  num 값 자체에 ++ 적용 → num 증가, pnum(포인터)은 그대로
*pnum++     →  *(pnum++) → pnum(포인터)에 ++ 적용 → pnum 이동, num은 그대로

(*pnum)++ : 괄호로 역참조(pnum = num 값)를 먼저 묶었으므로, ++는 **정수값**에 걸린다.

pnum++ : pnum이 ++와 먼저 묶이므로((pnum++)), ++는 **포인터 자신**에 걸린다. 는 **증가되기 전(옛날) 주소**를 역참조한다 — 그래서 결과값은 num의 현재 값과 같지만, num 자체는 바뀌지 않는다.

#### **포인터가 움직이는 양 = sizeof(가리키는 타입)**

포인터 증감은 "1바이트"가 아니라 **가리키는 자료형 크기만큼** 움직인다.

| **포인터 타입** | **1회 증감 이동량 (일반적 환경)** |
| --- | --- |
| char* | 1바이트 |
| int* | 4바이트 |
| double* | 8바이트 |

실제 테스트에서 int* 포인터가 pnum++ 후 주소가 정확히 4 증가하는 것을 확인했다.

### **4. 실행 예제**

#include <stdio.h>

int main() {
    int num = 10;
    int *pnum = &num;

    printf("*(pnum) = %d \n", *(pnum));          // 10
    printf("(*pnum)++ = %d \n", (*pnum)++);       // 10, num -> 11
    printf("(*pnum)+1 = %d \n", (*pnum)+1);       // 12 (num은 11 그대로)
    printf("*pnum+=1 = %d \n", *pnum+=1);         // num -> 12
    printf("(*pnum)+=1 = %d \n", (*pnum)+=1);     // num -> 13
    *pnum = *pnum + 1;
    printf("*pnum=*pnum+1 = %d \n", *pnum);       // num -> 14
    printf("++*pnum = %d \n", ++*pnum);           // num -> 15
    printf("++(*pnum) = %d \n", ++(*pnum));       // num -> 16

    return 0;
}

**출력**: 10 → 10 → 12 → 12 → 13 → 14 → 15 → 16

### **5. void 포인터는 왜 증감이 안 되는가**

void *mp = &num;
mp++;   // 표준 C: 컴파일 에러 (GNU 확장에서만 1바이트씩 허용)

포인터 증감은 sizeof(가리키는 타입)만큼 이동해야 하는데, void는 "타입 정보 없음"을 의미하므로 **몇 바이트를 움직여야 할지 계산 불가**.

pedantic-errors 옵션으로 컴파일하면 wrong type argument to increment 에러 발생 → 표준 C에서는 명백히 금지된 문법.

gcc 기본 모드에서 조용히 돌아가는 건 **GNU 확장**(void*를 char*처럼 취급) 때문이지, 표준 문법이 허용해서가 아니다.

#### **해결 방법**

// 방법 1: 다른 포인터 변수에 담아서 증가 (ip만 이동, mp는 그대로)
int *ip = (int*)mp;
ip++;

// 방법 2: mp 자신을 이동시키려면 재대입
mp = (int*)mp + 1;

> ❌ ((int*)mp)++; 는 **컴파일 에러** (lvalue required as increment operand). 캐스트 결과는 rvalue라서 ++를 적용할 "저장 공간"이 없다.
> 

### **6. lvalue vs rvalue (개인적으로 정리. 수업에선 다루지 않았음.)**

| **구분** | **의미** | **예시** | **& 가능?** | **대입 가능?** |
| --- | --- | --- | --- | --- |
| **lvalue** | 실제 메모리 공간(주소)을 가진 표현식 | num, *pnum | ✅ | ✅ |
| **rvalue** | 그 순간 계산되는 임시 값, 저장공간 없음 | 5, num+1, (int*)mp | ❌ | ❌ |

pnum은 역참조를 통해 num이 있는 실제 저장공간을 가리키므로 lvalue다. (&(*pnum)과 &num은 같은 주소를 가리킨다.)

(int*)mp 같은 캐스트 결과는 그 순간 만들어진 임시값(rvalue)이라서 주소를 뜰 수도, 대입할 수도, ++를 적용할 수도 없다.

**++/-/=는 모두 "그 자리에 값을 다시 쓰는" 연산이라서, 반드시 lvalue에만 적용 가능하다.**

### **7. 함수에 값만 넘기면 원본은 안 바뀐다 (call by value)**

void increment(int value) {
    value++;
}

int main() {
    int num = 10;
    increment(num);   // num의 "복사본"이 value로 전달됨
    // num은 여전히 10
}

increment(num)은 num의 **복사본**을 value에 넘기는 것(call by value)이라서, 함수 안에서 value를 아무리 바꿔도 main의 num은 영향을 받지 않는다. 또한 increment가 void이든 int를 return하든, **그 반환값을 호출부에서 받아서 쓰지 않으면 아무 의미가 없다.**

원본을 실제로 바꾸는 방법은 두 가지다.

// 방법 1: 반환값을 받아서 재대입
int increment(int value) { value++; return value; }
num = increment(num);

// 방법 2: 주소(포인터)를 넘겨서 원본을 직접 수정 (call by reference)
void increment(int *value) { (*value)++; }
increment(&num);

### **8. 함수 매개변수에서도 (*value)++와 value++는 다르다**

increment(int *value) 안에서도 2번 원칙이 똑같이 적용된다.

(*value)++   →  *value(= 호출부의 num)를 먼저 역참조 → num이 증가함 (올바른 사용)
*value++     →  *(value++) → value(포인터, 매개변수)만 다음 주소로 이동 → num은 그대로

value++;로 잘못 쓰면 컴파일러가 value computed is not used라는 경고까지 준다 — 역참조한 값을 구해놓고 아무 데도 안 쓰고 버린다는 뜻. 함수를 통해 원본 값을 바꾸고 싶다면 **반드시 (*value)++처럼 괄호로 역참조를 먼저 묶어야 한다.**

### **9. 배열을 함수 매개변수로 받을 때 — 포인터로 변환(decay)된다**

void function(int a[]);     // 겉보기엔 배열
void function(int *a);      // 실제로는 완전히 동일한 포인터

함수 인자로 배열을 넘기면 배열 전체가 복사되는 게 아니라, **배열의 첫 번째 원소를 가리키는 포인터로 자동 변환(decay)**되어 전달된다. 그래서 함수 매개변수 자리에서 int a[]와 int a[10]과 int *a는 컴파일러에게 전부 똑같이 취급된다(적어준 크기도 무시됨).

**증거**: 함수 안에서 sizeof(a)를 해보면 배열 크기가 아니라 **포인터 크기**가 나온다.

int arr[10];
sizeof(arr);              // 40  (main 안에서: 배열 전체 크기 = int 4바이트 × 10)

void f(int a[]) {
    sizeof(a);             // 8   (함수 안에서: 그냥 포인터 크기)
}

함수는 배열의 **길이 정보를 전혀 모른다** (첫 원소 주소만 받으므로). 그래서 배열을 함수에 넘길 때는 길이를 별도 인자로 같이 넘겨주는 게 일반적이다.

void process(int a[], int length) {
    for (int i = 0; i < length; i++) { /* a[i] 사용 */ }
}
process(arr, 10);

### **10. 포인터 크기는 가리키는 타입과 무관하게 항상 같다**

int*          → 8바이트
char*         → 8바이트
double*       → 8바이트
BigStruct*    → 8바이트  (BigStruct 자체는 32바이트여도 포인터는 8바이트)
void*         → 8바이트

포인터가 저장하는 건 "값 자체"가 아니라 **메모리 주소**이기 때문에, 가리키는 대상이 int든 거대한 구조체든 포인터의 크기는 항상 동일하다. 주소를 표현하는 비트 수는 가리키는 타입이 아니라 **시스템의 주소 체계(아키텍처)**가 결정한다.

> ⚠️ 단, "무조건 8바이트"는 C 언어의 절대 규칙이 아니라 **플랫폼에 따라 달라지는 값**이다. 64비트 시스템(지금 대부분의 PC)에서는 8바이트, 32비트 시스템에서는 4바이트다. "가리키는 자료형과 무관하게 일정하다"는 게 핵심이고, 정확한 바이트 수는 시스템에 달려 있다.

### 문자열

`''`(작은따옴표)와 `""`(큰따옴표)는 아예 다른 걸 의미한다.

- `'a'` → **문자 리터럴(character literal)**: 문자 하나, 그 자체가 값입니다. 끝에 `\0`이 안 붙는다.
- `"a"` → **문자열 리터럴(string literal)**: 문자들의 나열이고, **컴파일러가 자동으로 맨 끝에 `\0`(널 바이트)을 하나 더 붙는다.**
