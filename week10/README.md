## 11장 문자와 문자열

### 1. 문자 vs 문자열

| 구분 | 문자 | 문자열 |
|---|---|---|
| 표현 | `'H'` (작은따옴표) | `"H"` (큰따옴표) |
| 자료형 | `char` | `char` 배열 (별도 자료형 없음) |
| 크기 | 1바이트 | 글자 수 + 1바이트 (`'\0'`) |
| 끝 표시 | 없음 | 널 문자 `'\0'` (아스키코드 0) → 종료 신호, 길이 파악, 버퍼 오버플로 방지 |

### 2. 문자열 초기화 방법

| 방법 | 코드 | 특징 |
|---|---|---|
| 리터럴 | `char s[] = "Hello";` | 널 문자 자동 추가 |
| 문자 배열 | `char s[] = {'H','e','l','l','o','\0'};` | `'\0'` 직접 넣어야 함 |
| 크기 지정 | `char s[10] = "Hello";` | 크기 ≥ 길이 + 1 |
| 복사 함수 | `strcpy(s, "World");` | 널 문자까지 복사 |

#### ⭐ 널 문자를 고려한 배열 크기 지정

```c
char str[6] = {'s', 't', 'r', 'i', 'n', 'g'};   // ❌ 크기 6 → '\0' 들어갈 자리 없음
printf("%s", str);
```

| 항목 | 내용 |
|---|---|
| 원칙 | 배열 크기 = **글자 수 + 1** (`'\0'` 자리) → `"string"`(6글자)은 **크기 7** 필요 |
| `printf("%s")` 동작 | 배열 크기를 모름 → 시작 주소부터 **`'\0'`을 만날 때까지** 계속 출력 |
| 위 코드 실행 결과 | `string` 뒤에 **쓰레기 값이 붙어 출력**될 수 있음 (맥에서 실행 결과: `stringI�`) |
| 이유 | 배열 안에 `'\0'`이 없음 → 배열 끝을 넘어 옆 메모리까지 읽다가 우연히 0을 만나야 멈춤 (정의되지 않은 동작) |
| 주의 | 우연히 바로 뒤가 0이면 `string`만 정상 출력되기도 함 → **정상처럼 보여도 틀린 코드** |
| 해결 | `char str[7] = {'s','t','r','i','n','g','\0'};` 또는 `char str[] = "string";` (크기 7 자동) |

#### 배열 크기를 더 크게 잡은 경우

```c
char c[10] = "Hi";   // 메모리: 'H' 'i' 0 0 0 0 0 0 0 0
```

| 항목 | 내용 |
|---|---|
| 남은 공간 | 초기화하지 않은 나머지 칸은 **자동으로 0으로 채워짐** |
| 0과 널 문자 | `'\0'`의 아스키코드 = **0** → 0은 널 문자와 같다고 생각해도 됨 |
| 문자열의 끝 | **가장 처음 나온 0만 문자열의 끝(널 문자)** 으로 쓰임 → `printf("%s", c)` 결과: `Hi` |
| 나머지 0 | 문자열로는 읽히지 않는 **그냥 남은 공간의 0** |

### 3. ⭐ 문자열 포인터 vs 문자열 배열

> C에는 문자열 자료형이 없으므로 **문자형 포인터(`char *`)는 주로 문자열을 가리키는 데 사용** (첫 문자 주소 저장 → `'\0'`까지 따라감)

| 구분 | `char *string = "Hello"` | `char array[] = "Array"` |
|---|---|---|
| 유형 | 포인터 | 배열 |
| 저장 위치 | 읽기 전용 메모리 영역 | 스택 |
| 변경 가능성 | 문자열 자체는 변경 불가능 | 문자열 내용 변경 가능 |
| 메모리 할당 | 리터럴을 가리키는 포인터만 필요 → 메모리 할당이 덜 필요 | 널 문자를 포함한 문자열 크기만큼 할당 필요 |
| 용도 | 주소를 다른 문자열로 변경 가능, 원래 문자열은 변경 불가 | 문자열 내용을 자유롭게 변경 가능 |
| 주의 사항 | 포인터를 변경하면 원래 문자열에 다시 접근 불가 | 배열 크기는 선언 시 고정, 이후 변경 불가 |

### 4. ⭐ 문자열 수정 가능 여부

| 코드 | 가능? | 이유 / 결과 |
|---|---|---|
| `char a[] = "Hello"; a[1] = 'o';` | ⭕ | 배열에 복사된 내 메모리 → `"Hollo"` |
| `char *p = "Hello"; p[1] = 'o';` | ❌ | 읽기 전용 상수 → 실행 중 오류 (정의되지 않은 동작) |
| `a = "World";` | ❌ | 배열명은 상수 → 통째로 대입 불가, `strcpy(a, "World");` 사용 |
| `p = "World";` | ⭕ | 포인터가 가리키는 주소만 바뀜 |
| `const char *p = "Hello";` | 💡 | 리터럴 수정 실수를 컴파일 단계에서 막아줌 (권장) |

| 대입 값 | 의미 | `printf("%s", a)` 결과 |
|---|---|---|
| `a[1] = 'o';` | 영문자 o | `Hollo` |
| `a[1] = '0';` | 문자 '0' (아스키 48) | `H0llo` |
| `a[1] = 0;` | 널 문자 `'\0'` | `H` (문자열이 여기서 끝남) |
| `a[1] = o;` | 따옴표 없음 → 변수로 인식 | 컴파일 오류 |

### 5. 문자 입출력 함수

| 함수 | 헤더 | 원형 | 특징 |
|---|---|---|---|
| `getchar()` | `<stdio.h>` | `int getchar(void);` | 한 문자 입력, 입력 버퍼 사용 (Enter 필요), 화면에 보임 |
| `putchar()` | `<stdio.h>` | `int putchar(int c);` | 한 문자 출력 |
| ⭐ `_getch()` | `<conio.h>` | `int _getch(void);` | 키 누르면 **즉시 반환** (Enter 불필요), **입력한 문자가 화면에 안 보임** (비밀번호 입력 등) |
| `_putch()` | `<conio.h>` | `int _putch(int c);` | 버퍼링 없이 콘솔에 즉시 출력 |

### 6. ⭐ `getchar()` / `putchar()`가 `int`를 쓰는 이유

| 항목 | 내용 |
|---|---|
| 반환/인수 형식 | 문자를 **아스키코드(정수)** 로 주고받음 → 변수형을 **`int`** 로 지정 |
| 예시 | `int ch = getchar();` 에서 `'A'` 입력 → `ch` = 65, `putchar(65)` → `A` 출력 |
| EOF 구별 | 입력 끝/오류 시 **EOF(-1)** 반환 → 일반 문자(0~255)와 구별하려면 `int` 필요 |

## 13장 구조체

### 1. 구조체 개요

| 항목 | 내용 |
|---|---|
| 정의 | 서로 **다른 자료형**의 데이터를 하나로 묶는 사용자 정의 자료형 (파생 자료형) |
| 배열과 차이 | 배열 = 같은 자료형의 집합 / 구조체 = 다른 자료형의 집합 |
| 멤버(필드) | 구조체 안의 각 변수 |

### 2. 선언 / 초기화 / 접근

| 작업 | 코드 |
|---|---|
| 선언 | `struct Student { char name[20]; int id; float gradePoints; };` |
| 초기화 | `struct Student s1 = {"홍길동", 2024001, 4.2f};` (멤버 순서대로) |
| 변수로 접근 | `s1.id = 2024002;` (점 `.` 연산자) |
| 포인터로 접근 | `p->gradePoints = 3.9f;` (화살표 `->` 연산자) |

#### ⭐ 구조체 멤버 접근 연산자

> **구조체의 멤버에 접근하려면 점(`.`) 연산자를 사용한다.**

| 항목 | 내용 |
|---|---|
| 형식 | `구조체변수.멤버이름` |
| 값 넣기 | `s1.id = 2024001;` / `s1.gradePoints = 4.2f;` |
| 값 읽기 | `printf("%d", s1.id);` |
| 문자열 멤버 | `strcpy(s1.name, "홍길동");` (배열이라 `s1.name = "홍길동";` ❌) |
| 포인터일 때 | `.` 대신 화살표 `->` 사용 → `p->id` (= `(*p).id`) |

#### ⭐ 구조체 포인터와 화살표(`->`) 연산자

> **구조체에서는 화살표(`->`) 연산자를 많이 사용한다.** (구조체 포인터로 멤버에 접근할 때)

```c
struct Student student1;
struct Student *ptr = &student1;    // ptr이 student1의 주소를 저장

strcpy(ptr->name, "Moon");    // 포인터 ptr로 student1의 멤버 name에 접근
ptr->id = 20240001;           // 포인터 ptr로 student1의 멤버 id에 접근
ptr->gradePoints = 88.5;      // 포인터 ptr로 student1의 멤버 gradePoints에 접근
```

| 항목 | 내용 |
|---|---|
| 형식 | `구조체포인터->멤버이름` |
| 의미 | `ptr->id` = `(*ptr).id` → 포인터가 가리키는 구조체의 멤버 |
| 결과 | `ptr`로 바꾼 값 = **`student1`의 값이 바뀜** (같은 메모리) |
| 많이 쓰는 이유 | 구조체를 함수에 **포인터로 전달**하는 경우가 많음 (복사 없이 효율적, 원본 수정 가능) |
| | `(*ptr).id`는 괄호가 필요해 불편 → `ptr->id`가 더 간단하고 읽기 쉬움 |
| 주의 | `*ptr.id`는 `*(ptr.id)`로 해석됨 → 오류 (`.`이 `*`보다 우선순위 높음) |

### 3. 중첩 구조체

| 형태 | 예시 | 접근 |
|---|---|---|
| 구조체 변수를 멤버로 | `struct Person { struct Date birthdate; };` | `person.birthdate.year` |
| 구조체 포인터를 멤버로 | `struct Employee { struct Address *address; };` | `emp.address->street` |
| 장점 | 데이터를 논리적으로 묶어 구조가 명확, 재사용 가능 | |

#### ⭐ 구조체 포인터를 멤버로 가진 구조체 (Employee → Address)

> **Employee 구조체는 직원의 이름과 주소 정보를 저장하는데, 주소 정보는 Address 구조체에 대한 포인터로 선언되어 있어 동적 메모리 할당을 통해 할당하거나 기존의 Address 구조체 변수를 참조할 수 있다.**

```c
struct Address  { char street[50]; char city[50]; char state[50]; int zipCode; };
struct Employee { char name[50]; struct Address *address; };   // 주소는 포인터로 선언

struct Employee emp;
struct Address addr;
```

| 항목 | 내용 |
|---|---|
| Address | 거리(`street`), 도시(`city`), 주(`state`), 우편번호(`zipCode`) 필드 보유 |
| Employee | 이름(`name`) + **Address 구조체 포인터**(`address`) |
| 방법 ① 기존 변수 참조 | `emp.address = &addr;` → 이미 있는 `addr`의 주소 저장 |
| 방법 ② 동적 메모리 할당 | `emp.address = (struct Address *)malloc(sizeof(struct Address));` → 사용 후 `free(emp.address);` |
| 멤버 접근 | `emp`는 변수라 `.`, `address`는 포인터라 `->` → `strcpy(emp.address->city, "Seoul");` |
| 주의 | 포인터는 주소만 저장 → ①이나 ②로 **연결하기 전에 사용하면 오류** |

#### ⭐ 포인터 멤버를 통한 접근: `emp.address->street`

> **Employee 구조체의 멤버 address를 통해 Address 구조체의 멤버에 접근할 때는 화살표 연산자(`->`)를 사용한다.**
> **emp의 포인터 address가 가리키는 Address 구조체의 멤버 street에 접근하려면 `emp.address->street`라고 작성한다.**

```c
strcpy(emp.address->street, "서울시");   // 문자 배열 멤버 → strcpy
emp.address->zipCode = 123456;           // 정수 멤버 → = 대입
```

| 단계 | 코드 | 연산자 | 이유 |
|---|---|---|---|
| ① | `emp` | | Employee 구조체 **변수** |
| ② | `emp.address` | `.` | 변수의 멤버 접근 → 결과는 Address **포인터** |
| ③ | `emp.address->street` | `->` | 포인터가 가리키는 구조체의 멤버 접근 |

| 비교 | 의미 |
|---|---|
| `emp.address->street` | ⭕ 올바른 표현 |
| `(*emp.address).street` | ⭕ 위와 같은 의미 (괄호 필요해 불편) |
| `emp.address.street` | ❌ `address`는 포인터라 `.` 사용 불가 → 컴파일 오류 |
| `emp->address->street` | ❌ `emp`는 포인터가 아닌 변수라 `->` 사용 불가 |

> 💡 규칙: **왼쪽이 변수면 `.`, 왼쪽이 포인터면 `->`**

#### ⭐ `->` 동작 원리 자세히 (13-3.c 기준)

> **`->` = "이 주소로 찾아가서, 거기 있는 멤버를 꺼내라"**
> `emp.address->street`는 설계도(Address 구조체)가 아니라, 포인터가 가리키는 **실제 변수 `addr`의 street**에 접근한다.

```
emp                              addr  (주소 0x1000에 있음)
┌────────────────────┐           ┌─────────────────────────┐
│ name: "문석재"     │           │ street:  "천호대로"  ◀── ④
│ address: 0x1000 ───┼── ③ ──▶   │ city:    "서울"          │
└────────────────────┘           │ state:   "광진구"        │
        ②                        │ zipCode: 134819          │
                                 └─────────────────────────┘
```

| 단계 | 코드 | 뜻 | 결과 |
|---|---|---|---|
| ① | `emp` | 직원 변수 | Employee 구조체 |
| ② | `emp.address` | emp 안의 `address` 칸을 꺼냄 | **addr의 주소값** (예: `0x1000`) |
| ③ | `->` | 그 주소로 **찾아감** | **addr 변수**에 도착 |
| ④ | `street` | 도착한 곳의 `street` 멤버 | `addr.street` = `"천호대로"` |

| 코드 | 실제로 접근하는 곳 | 13-3.c 값 |
|---|---|---|
| `emp.address->street` | `addr.street` (거리) | 천호대로 |
| `emp.address->city` | `addr.city` (도시) | 서울 |
| `emp.address->state` | `addr.state` (구) | 광진구 |
| `emp.address->zipCode` | `addr.zipCode` (우편번호) | 134819 |

> 같은 메모리를 가리키므로 `fgets(emp.address->street, ...)`로 입력하면 실제로는 **`addr.street`에 저장**됨

#### 💡 왜 구조체 안에 포인터 멤버를 넣을까?

| 항목 | 내용 |
|---|---|
| `struct Address* address;` | 주소를 저장할 **칸(연결 고리)을 만듦** → 이 칸이 없으면 `emp.address = &addr;` 자체를 쓸 수 없음 |
| `emp.address = &addr;` | 그 칸에 addr의 주소를 넣어 **실제로 연결** |
| 짧은 예제에서는 | `addr.city`를 직접 써도 결과 같음 → 13-3.c는 문법 연습용 |
| 진짜 필요한 경우 | **emp 하나만 넘겨도 주소까지 찾아갈 수 있음** → `printEmployee(emp)`처럼 함수·배열(`staff[i].address->city`)로 다룰 때 편리 |
| 그 외 장점 | 메모리 절약 (포인터 8바이트), 여러 직원이 **같은 주소 공유** 가능, 필요할 때 `malloc`으로 생성 |
| 주의 | 연결(`&addr` 또는 `malloc`) 전에 `->` 사용하면 쓰레기 주소 접근 → 프로그램이 죽을 수 있음 |

### 4. 구조체 변수의 대입 (`=`)

| 멤버 종류 | 복사 방식 |
|---|---|
| 기본 자료형·배열 | **깊은 복사** (값 자체 복사) |
| 포인터 | **얕은 복사** (주소만 복사, 데이터 공유) |

> 같은 자료형의 구조체끼리만 `=`로 전체 복사 가능

### 5. 구조체 배열

| 항목 | 내용 |
|---|---|
| 의미 | 같은 구조체 여러 개를 연속 저장 |
| 초기화 | `struct Person people[5] = {{"Kim", 20}, {"Lee", 22}};` (자동 초기화 안 됨) |
| 접근 | `people[3].age = 25;` / `strcpy(people[3].name, "Park");` |

### 6. 구조체 포인터 연산자

| 표현 | 의미 |
|---|---|
| `(*p).name` | p가 가리키는 구조체의 멤버 name |
| `p->name` | 위와 동일 (주로 사용) |
| `*p.name` | `*(p.name)` → 멤버 name이 가리키는 내용 |
| `*p->name` | `*(p->name)` |

### 7. 구조체를 함수 인수로 전달

| 방식 | 선언 | 특징 |
|---|---|---|
| 값 전달 | `void f(struct Person p)` | 복사본 → 원본 변경 없음, 큰 구조체는 메모리·성능 부담 |
| 포인터 전달 | `void f(struct Person *p)` | 주소만 전달 → 효율적, **원본 수정 가능** (`p->age++`) |

### 9. 공용체 vs 열거형

| 구분 | 공용체 (`union`) | 열거형 (`enum`) |
|---|---|---|
| 의미 | 여러 멤버가 **같은 메모리 공유** | 관련된 **정수 상수 집합**에 이름 부여 |
| 크기 / 값 | 가장 큰 멤버의 크기 | 기본 0부터 1씩 증가, 직접 지정 가능 |
| 특징 | 한 번에 **하나의 멤버만 유효** (마지막 저장값) | 가독성 ↑, 오류 ↓ |
| 예시 | `union Data { int i; float f; char str[20]; };` | `enum Color { RED, GREEN, BLUE };` (0, 1, 2) |

## 이분 탐색 (Binary Search)

> **정렬된 배열에서 가운데 값과 비교해 탐색 범위를 절반씩 줄여 가며 값을 찾는다.**

| 항목 | 내용 |
|---|---|
| ⭐ 전제 조건 | 배열이 **오름차순 또는 내림차순으로 정렬**되어 있어야 함 (정렬 안 되어 있으면 사용 불가) |
| 정렬 방향 | 아래 코드는 **오름차순** 기준 → 내림차순 배열이면 `low`/`high` 이동 방향을 반대로 |
| 방법 | `mid = (low + high) / 2` → 찾는 값과 `arr[mid]` 비교 |
| 같으면 | 찾음 → `mid` 반환 |
| 찾는 값이 더 크면 | 오른쪽 절반 탐색 → `low = mid + 1` |
| 찾는 값이 더 작으면 | 왼쪽 절반 탐색 → `high = mid - 1` |
| 종료 | `low > high` → 값이 없음 (`-1` 반환) |
| 시간 복잡도 | **O(log n)** (예: 1,000개 → 최대 약 10번 비교) |
| 순차 탐색과 비교 | 순차 탐색은 처음부터 하나씩 → **O(n)**, 정렬 안 된 배열에도 사용 가능 |

```c
int binarySearch(int arr[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;    // 가운데 위치
        if (arr[mid] == key) return mid;    // 찾음
        else if (arr[mid] < key) low = mid + 1;    // 오른쪽 절반으로
        else high = mid - 1;    // 왼쪽 절반으로
    }
    return -1;    // 없음
}
```

| 예: `{1, 3, 5, 7, 9, 11, 13}`에서 9 찾기 | low | high | mid | `arr[mid]` | 결과 |
|---|---|---|---|---|---|
| 1회 | 0 | 6 | 3 | 7 | 9 > 7 → 오른쪽 |
| 2회 | 4 | 6 | 5 | 11 | 9 < 11 → 왼쪽 |
| 3회 | 4 | 4 | 4 | 9 | **찾음 (인덱스 4)** |

## ✅ 핵심 요약

| 주제 | 기억할 내용 |
|---|---|
| 문자열 | `char` 배열 + 끝의 `'\0'` |
| ⭐ 배열 크기 | **글자 수 + 1** (`'\0'` 자리), `printf("%s")`는 `'\0'`까지 출력 → 없으면 쓰레기 값 |
| ⭐ 문자형 포인터 | `char *`는 주로 **문자열을 가리키는 데** 사용 (첫 문자 주소 저장) |
| ⭐ 수정 가능 여부 | 리터럴 포인터는 **수정 불가**, 문자 배열은 **요소 수정 가능** (단, `=`로 통째 대입은 불가) |
| ⭐ `getchar()`/`putchar()` | 문자를 **아스키코드(int)** 로 주고받음 → 변수형 **`int`** (EOF 구별 목적도 있음) |
| ⭐ `_getch()` | Enter 없이 즉시 입력, **입력 문자가 화면에 안 보임** |
| 입력 함수 | `gets()` 대신 **`fgets()`** 사용 |
| 헤더 | 문자 처리 `<ctype.h>`, 문자열 처리 `<string.h>` |
| 구조체 접근 | 변수는 `.`, 포인터는 `->` |
| 함수 전달 | 큰 구조체는 **포인터로 전달**이 효율적 |
| 공용체 / 열거형 | 메모리 공유 / 이름 있는 정수 상수 |
| 이분 탐색 | **오름차순/내림차순으로 정렬된 배열**에서 가운데와 비교해 범위를 절반씩 줄임 → **O(log n)** |
